# 대전 아파트 매매가 예측

아파트의 면적·층·건축년도·역까지 거리 같은 기본 속성만으로 매매가(만원)를 예측하는 회귀 문제입니다. 『핸즈온 머신러닝(3판)』 2장 "머신러닝 프로젝트 처음부터 끝까지"에서 캘리포니아 주택 가격을 다루며 익힌 절차를, 우리 지역 데이터 구조에 그대로 적용해 보는 것이 목표입니다.

> 데이터 안내: 이 데이터는 수업용으로 **생성한 합성 데이터**입니다. 대전의 실제 거래 기록이 아니므로 분석 결과를 실제 시장 해석에 사용하면 안 됩니다. 다만 변수 간 관계는 실제 주택 시장과 비슷한 방향으로 설계되어 있습니다.

## 데이터

| 파일 | 내용 |
|---|---|
| `train.csv` | 2,800건. 입력 변수 9개 + 정답 `price` |
| `test.csv` | 1,200건. 입력 변수만 포함 (이 데이터의 `price`를 예측해 제출) |
| `sample_submission.csv` | 제출 파일 형식 예시 (모든 행을 학습 데이터 평균가로 채운 것) |

| 열 | 설명 | 값 범위(학습 데이터) |
|---|---|---|
| `id` | 매물 식별자 | |
| `gu` | 자치구 (범주형) | 유성구·서구·중구·동구·대덕구 |
| `area_m2` | 전용면적 (㎡) | 33 ~ 210 |
| `floor` | 층 | 1 ~ 31 |
| `built_year` | 건축년도 | 1988 ~ 2024 |
| `subway_dist_m` | 가장 가까운 도시철도역까지 거리 (m) | 60 ~ 4,500 |
| `rooms` | 방 개수 | 1 ~ 6 |
| `parking_per_hh` | 세대당 주차대수 | 0.3 ~ 1.9 |
| `brand` | 브랜드 아파트 여부 (0/1) | |
| `price` | **매매가 (만원) — 예측 대상** | 5,900 ~ 63,400 (중앙값 22,300) |

결측치는 없습니다. 변수들은 모두 숫자형이고 `gu`만 범주형입니다.

## 평가

- 지표: **RMSE** (Root Mean Squared Error) -> 낮을수록 좋습니다.
- 리더보드의 **Public 점수**는 테스트 데이터 가운데 30%(360건)로 계산되며, 마감 후 나머지 70%(840건)로 **Private(최종) 순위**를 산정합니다. Public 점수에만 맞추면 최종 순위가 내려갈 수 있습니다.
- 최종 평가에는 각 참가자(팀)의 Public 점수 상위 **2개** 제출물 가운데 Private 점수가 더 좋은 것을 사용합니다.
- 참고치: 모든 행을 학습 데이터 평균가로 예측하면 RMSE가 약 8,700 수준입니다. 간단한 선형회귀(가격 로그 변환, `gu` 원-핫 인코딩)만으로 3,300 안팎까지 내려가고, 트리 앙상블을 쓰면 3,000 아래도 가능합니다. 그 아래로 얼마나 줄이느냐가 과제입니다.

## 제출 형식

`sample_submission.csv`와 같은 두 열의 CSV 파일입니다. `test.csv`의 1,200개 `id`가 빠짐없이 한 번씩 있어야 하며, `price`는 숫자여야 합니다.

## 권장 진행 순서

1. **문제 정의와 지표 확인** — 회귀 문제, 평가지표 RMSE. 학습 데이터에서 검증용 데이터를 떼어 두고(`train_test_split` 또는 면적 구간을 기준으로 한 `StratifiedShuffleSplit`), 리더보드 점수와 검증 점수가 비슷하게 움직이는지 확인하면서 진행합니다.
2. **데이터 탐색** — 히스토그램으로 분포와 왜도(가격·역거리)를 확인하고, 산점도와 상관계수로 면적·건축년도·거리와 가격의 관계를 봅니다. 자치구별 중앙값 비교도 해 보십시오.
3. **데이터 준비** — `ColumnTransformer`와 `Pipeline`으로 전처리를 한 덩어리로 묶습니다. 수치형은 `StandardScaler`, 범주형 `gu`는 `OneHotEncoder`. 왜도가 큰 변수의 로그 변환, 건물 연식(`2026 - built_year`)이나 방당 면적 같은 파생 변수 추가, 타깃의 로그 변환(`TransformedTargetRegressor`)을 실험해 보십시오.
4. **모델 선택과 훈련** — `LinearRegression` → `DecisionTreeRegressor` → `RandomForestRegressor` 순으로 비교하고, `cross_val_score`(RMSE)로 과대적합 여부를 확인합니다.
5. **세부 튜닝** — `GridSearchCV` 또는 `RandomizedSearchCV`로 하이퍼파라미터를 조정하고, 특성 중요도를 살펴 불필요한 변수를 정리합니다. 그레이디언트 부스팅(`HistGradientBoostingRegressor`) 등 다른 모델도 시도해 볼 수 있습니다.
6. **제출** — 최종 파이프라인을 학습 데이터 전체로 다시 학습한 뒤 `test.csv`를 예측해 제출합니다. 제출 메모에 사용한 모델과 특성을 적어 두면 나중에 비교하기 좋습니다.

## 규칙

- 제출은 하루 **5회**까지(한국 시간 자정에 초기화, 팀은 팀 전체가 공유). 형식 오류로 채점되지 않은 제출은 횟수에 포함되지 않습니다.
- 외부 데이터는 사용하지 않습니다(합성 데이터이므로 외부 자료와 결합할 수 없습니다).
- 테스트 데이터 정답 추정을 위한 리더보드 탐색(probing)은 금지되며, 적발 시 부정행위로 처리됩니다.
- 다른 참가자의 제출 파일을 그대로 내면 **자동으로 탐지되며, 부정행위로 처리됩니다.**
- **노트북 제출은 필수**입니다. 모든 참가자(팀)는 최종 제출물을 재현할 수 있는 노트북(`.ipynb`)을 LMS 과제함에 제출해야 하며, 노트북을 내지 않았거나 노트북으로 예측이 재현되지 않으면 리더보드 점수는 인정되지 않습니다. 제출 기한은 LMS 공지를 따릅니다.
